# fuadFolio

Personal portfolio website for **Al Fahim Fuad** — Data Scientist, ML Engineer, and AI Builder. Built with Django and a hand-crafted, fully responsive design system.

Live sections: Home (hero, skills, services), About (bio + education journey), Projects (live GitHub repos), and Contact.

## Stack

- **Language**: Python 3.12
- **Framework**: Django 6.0
- **Database**: PostgreSQL (Replit-managed, via `DATABASE_URL`). Falls back to SQLite if `DATABASE_URL` is not set.
- **Static files**: WhiteNoise
- **Production server**: Gunicorn

## Project Layout

- `FuadFolio/` — Django project package (settings, urls, wsgi/asgi)
- `home/`, `about/`, `portfolio/`, `contact/` — Django apps
- `templates/` — shared HTML templates
- `static/` — source static assets (css, images, favicon)
- `staticfiles/` — collected static files (used in production)
- `media/` — user-uploaded files (profile photo, CV/resume, education images)
- `manage.py` — Django management entrypoint

## Running

The `Start application` workflow runs:

```
python manage.py runserver 0.0.0.0:5000
```

The app listens on port 5000 and is served through the Replit preview proxy.

## Deploying to Render or Railway (with Neon Postgres)

The app is ready to deploy as-is on Render, Railway, or Replit — same codebase,
just different env vars per platform. Both `render.yaml` and `railway.json`
are already in the repo.

1. **Create a Neon database** at [neon.tech](https://neon.tech) and copy its
   connection string (starts with `postgresql://...`, includes `sslmode=require`).
2. **Push this repo to GitHub** (Render/Railway both deploy from a Git repo).
3. **Render**:
   - New → Blueprint → pick the repo → Render reads `render.yaml` automatically.
   - In the service's Environment tab, paste the Neon connection string into
     `DATABASE_URL` (left blank in the blueprint on purpose). `SECRET_KEY` is
     auto-generated by Render; `DEBUG` is already set to `False`.
   - Deploy. Render runs `collectstatic` + `migrate` on every build automatically.
4. **Railway**:
   - New Project → Deploy from GitHub repo → Railway detects `railway.json`
     and uses Nixpacks to build.
   - In Variables, set `DATABASE_URL` (the Neon connection string), `SECRET_KEY`
     (any long random string), and `DEBUG=False`.
   - Railway auto-assigns `$PORT`; the start command in `railway.json` already
     runs `migrate` + `collectstatic` before starting Gunicorn.
5. **Either platform** — after the first deploy, create an admin user with a
   one-off shell command (`python manage.py createsuperuser`) so you can log
   into `/admin/` and fill in the `Profile` row (photo, CV content) and
   `Education` entries.

`CSRF_TRUSTED_ORIGINS` in `FuadFolio/settings.py` already trusts
`*.onrender.com` and `*.up.railway.app`/`*.railway.app`. If you attach a
custom domain on either platform, add it via a comma-separated
`CSRF_EXTRA_ORIGINS` env var, e.g. `https://yourdomain.com`.

## Features

- **Responsive design system** — one CSS file with breakpoints tuned for desktop, laptop, tablet, and mobile; consistent spacing/alignment across all of them.
- **GitHub-driven Projects page** — `home/github_api.py` pulls live public repos from `https://api.github.com/users/<SITE_GITHUB_USERNAME>/repos` (cached 30 minutes); push a new public repo and it appears automatically, no admin edit needed.
- **Centralized site identity** — `FuadFolio/settings.py` defines `SITE_GITHUB_USERNAME`, `SITE_EMAIL`, `SITE_LINKEDIN_URL`, `SITE_FACEBOOK_URL`; exposed to every template via `home/context_processors.py` as `{{ site.* }}` instead of hardcoding contact info in multiple places.
- **Download CV (auto-generated, ATS-friendly)** — the navbar "Download CV" button (route: `home/cv/`, view: `home.views.download_cv`) builds a clean, modern PDF resume on every request using `home/cv_generator.py` (ReportLab). It pulls:
  - **Projects** live from the GitHub REST API (top repos by stars/recency) — a new public repo shows up automatically.
  - **Education** live from the `about.Education` admin model.
  - **Name, title, summary, skills, experience, certifications** from the `Profile` row in `/admin/` — edit any of these and the very next download reflects it. Nothing is cached to disk, so there's no separate "regenerate" step.
- **Profile photo fallback** — uses the uploaded `Profile.photo` if set in `/admin/`, otherwise falls back to the real GitHub avatar.
- **Education Journey** — About page lists School (Anjuman Adarsha Govt. High School, Netrakona), College (Agricultural University College), and University (East West University) with real logos/photos, editable via `/admin/` (`about.Education`).

### New features (added on top — existing behaviour unchanged)

- **Navbar: Home · About · Projects · Others · My World · theme toggle · Download CV**
  Two distinct pages sit behind the nav:

  - **Others** (route `/others/`, app `professional`) — the professional
    showcase. Renders a work-experience timeline, certifications grid,
    achievements list, skills + core competencies, languages, and
    interests. Each section is admin-editable via three new models
    (`professional.Experience`, `professional.Certification`,
    `professional.Achievement`). The summary, skills, languages, and
    interests still come from the existing `home.Profile` row — edit it
    once and both the CV PDF and the Others page reflect it.
  - **My World** (route `/myworld/`, app `others`) — the personal
    playground. Two admin-editable sections:

    - **Personal Games** — add a `Game` row in `/admin/others/game/` with a
      title, description, embeddable play URL (itch.io, an HTML5 build, or
      any URL loadable in an iframe), and a cover image. Visitors click the
      card and the game opens inside an embedded modal — no page reload.
    - **Video Links** — add a `VideoLink` row in
      `/admin/others/videolink/` with a YouTube / Vimeo / direct-embed
      URL. The view auto-converts YouTube watch URLs into embeddable form
      and pulls a thumbnail from YouTube when no custom thumbnail is
      uploaded.

- **Day / Night theme toggle** — a sun/moon button in the navbar flips the
  whole site between the original light glassmorphic theme and a new dark
  theme. The choice is saved in `localStorage` and applied before first
  paint (no flash). On first visit it follows the OS `prefers-color-scheme`.

- **Project images — admin-editable / deletable** — the existing `Project`
  model already had an `image` field. It is now wired into the Projects
  page:
  - In `/admin/portfolio/project/`, each row shows a live image preview
    plus a "Has image" flag. Use the standard Django admin to **upload,
    replace, or clear** the image (tick the "Clear" checkbox and save to
    delete it).
  - When a `Project.title` exactly matches a GitHub repo name, its image
    overrides the placeholder thumbnail on the Projects page. When no
    GitHub repo matches, the entry is shown under a separate **Showcase**
    band.
  - When `CLOUDINARY_URL` (or `CLOUDINARY_CLOUD_NAME` + key + secret) is
    set, all uploads go straight to Cloudinary. Otherwise the project
    falls back to local `media/` storage — nothing breaks in development.

- **Cloudinary image storage** — set `CLOUDINARY_URL` (preferred) or the
  three individual env vars. Every `ImageField` (profile photo, project
  image, education image, others-page covers) is then routed through
  `cloudinary_storage.storage.MediaCloudinaryStorage` automatically.

- **Neon Postgres** — already supported out of the box via `DATABASE_URL`.
  Create a Neon database at [neon.tech](https://neon.tech), copy the
  connection string (it includes `sslmode=require`), and set it as
  `DATABASE_URL`. The app auto-detects it and switches from SQLite to
  Postgres.

- **Floating chatbot (Groq → OpenRouter failover)** — a chat bubble in the
  bottom-right corner opens a widget that answers questions about the site
  owner. The backend (`chatbot/llm.py`) tries **Groq** first; on a 429
  (rate limit) or any 5xx / network error, it automatically fails over to
  **OpenRouter** ("ekta limit sesh hole onnota start hbe"). If neither
  provider is configured or both fail, a friendly offline reply is shown
  so the widget never displays a raw error. Conversation history is held
  in the browser and sent on each request, so the backend stays stateless.

## Configuration Notes

- `ALLOWED_HOSTS = ['*']` and `CSRF_TRUSTED_ORIGINS` cover the Replit preview proxy.
- `DEBUG` defaults to `True` in development; set the `DEBUG` env var to `False` for production behavior.
- WhiteNoise serves static files; media (photo, CV, education images) is served via Django in development and should be backed by persistent/object storage in production.
- All contact/social URLs (`SITE_EMAIL`, `SITE_LINKEDIN_URL`, `SITE_FACEBOOK_URL`, `SITE_GITHUB_USERNAME`) are overridable via environment variables without touching template code.

## Admin

Manage content at `/admin/`:
- **Profile** — profile photo plus CV content fields (title, location, summary, skills, experience, certifications) that feed the auto-generated "Download CV" PDF AND the Others (professional) page.
- **Education** — School/College/University entries shown on the About page and included in the generated CV.
- **Portfolio → Projects** — upload, replace, or clear the image for a project. If the title matches a GitHub repo name, the image overrides that repo's placeholder thumbnail; otherwise the entry appears under a separate **Showcase** band on the Projects page.
- **Professional → Work experience** — add jobs (role, organisation, period, location, bullet points, current flag, link). Rendered as a timeline on the Others page.
- **Professional → Certifications** — add certificates (title, issuer, date, credential ID, verify URL, optional badge image).
- **Professional → Achievements** — add achievements (title, description, date, link, optional emoji icon).
- **Others → Personal games** — add mini-games (title, description, embeddable play URL, cover image). Visitors click a card and the game opens in an embedded modal.
- **Others → Video links** — add videos (title, description, watch URL, optional thumbnail, optional duration). YouTube URLs are auto-converted into embeddable form.

## Environment variables

A ready-to-use `.env.example` file is included in the project root.
Copy it to `.env` and fill in the values you need (python-dotenv is
already in `requirements.txt`, so a `.env` file is auto-loaded in
development). On Render / Railway / Koyeb, set the same keys in the
service's Environment tab instead.

| Variable | Purpose | Required |
| --- | --- | --- |
| `DATABASE_URL` | Neon Postgres connection string (starts with `postgresql://…`). Falls back to local SQLite if unset. | Production only |
| `SECRET_KEY` | Django secret. Auto-generated on Render; set manually on Railway. | Production |
| `DEBUG` | `True` / `False`. Defaults to `False`. | Production |
| `SITE_GITHUB_USERNAME` | GitHub username used for projects + avatar fallback. Default `alfahim-fuyad`. | No |
| `SITE_EMAIL` / `SITE_LINKEDIN_URL` / `SITE_FACEBOOK_URL` | Contact info exposed to templates as `{{ site.* }}`. | No |
| `SITE_FULL_NAME` / `SITE_TITLE` | Used by the chatbot's system prompt and the Others page header. Defaults to `Al Fahim Fuad` / `Data Scientist \| ML Engineer \| AI Builder`. | No |
| `GITHUB_TOKEN` | Optional GitHub PAT to lift the unauthenticated rate limit. | No |
| `CLOUDINARY_URL` | Cloudinary connection string (`cloudinary://…`). When set, all image uploads go to Cloudinary. | No |
| `CLOUDINARY_CLOUD_NAME` + `CLOUDINARY_API_KEY` + `CLOUDINARY_API_SECRET` | Alternative to `CLOUDINARY_URL` (set all three). | No |
| `GROQ_API_KEY` | Primary chatbot provider. Get one at [console.groq.com](https://console.groq.com). | No |
| `GROQ_MODEL` | Default `llama-3.3-70b-versatile`. | No |
| `OPENROUTER_API_KEY` | Fallback chatbot provider, used when Groq hits a rate limit. Get one at [openrouter.ai](https://openrouter.ai). | No |
| `OPENROUTER_MODEL` | Default `openai/gpt-4o-mini`. | No |
| `OPENROUTER_HTTP_REFERER` | Optional referer for OpenRouter attribution. | No |

## Deployment

Configured for Replit Autoscale:

- Build: `python manage.py collectstatic --noinput && python manage.py migrate --noinput`
- Run: `gunicorn --bind=0.0.0.0:5000 --reuse-port FuadFolio.wsgi:application`
